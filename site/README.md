# Docs site

Source for [spicetify.yusufaf.dev](https://spicetify.yusufaf.dev/), the docs hub for my
[Spicetify](https://spicetify.app/) extensions. Built with [Astro](https://astro.build/) and
[Starlight](https://starlight.astro.build/), deployed to GitHub Pages.

## How it builds

Each extension's README (`extensions/<slug>/README.md` in this repository) is the single source
of truth: the same file is the Spicetify Marketplace listing and the page on this site.

- `scripts/sync-extensions.mjs` runs before every `dev` and `build`. For each extension listed
  in `src/data/extensions.mjs`, it reads the extension's entry in the root `manifest.json`, its `README.md` and
  `CHANGELOG.md`, and its version from the root `.release-please-manifest.json`, and writes `src/content/docs/<slug>/index.md`, `changelog.md`, and
  `src/data/extensions.generated.json` for the landing-page shelf. All of it is gitignored.
  It also reads each preview image's dimensions: a preview at least 600px on its short side
  becomes that extension's og:image (square ones also get `twitter:card=summary`), written
  into the generated pages' frontmatter `head`. Every other page uses `public/og.png`.
- `src/lib/transformReadme.mjs` turns a README into a page: it drops the leading H1,
  strips `<!-- site:skip-start -->` … `<!-- site:skip-end -->` blocks (content meant for
  GitHub and Marketplace only), and makes relative links and images absolute.
- A missing manifest entry or README fails the build, so a broken extension never ships an
  empty page. So does a `manifest.json` entry with no matching `EXTENSIONS` entry.
- Hand-written pages (landing page, getting started, troubleshooting, developers) live at the
  top level of `src/content/docs/`, and hand-written guides in `src/content/docs/guides/`.
  Every other subdirectory there (`src/content/docs/*/`) is gitignored and regenerated by the
  sync, so don't put hand-written pages in one. An extension slug must be a plain lowercase
  name that isn't `guides`, a top-level page, `404` or `pagefind` (`src/lib/checkSlugs.mjs`);
  the sync refuses anything else.

To change an extension's page, edit its README. `docs.yml` rebuilds and deploys on every push to
`main` that touches `site/`, `extensions/`, `manifest.json` or `.release-please-manifest.json`.

## Development

Uses pnpm. Run these in `site/`, or as `pnpm -C site <script>` from the repo root.

```bash
pnpm install
pnpm dev         # sync extension pages, then start the dev server
pnpm build       # sync, then build to dist/
pnpm preview     # serve the built site
pnpm sync        # regenerate extension pages without building
pnpm test        # vitest (transformReadme, ogImage)
pnpm typecheck   # astro check
```

`pnpm typecheck` needs the generated files, so run `pnpm sync` (or `pnpm dev`) first on a
fresh clone. `src/data/extensions.generated.json` is gitignored.

## Adding an extension

Add an entry to `EXTENSIONS` in `src/data/extensions.mjs`. Its `slug` is the extension's folder
under `extensions/` and becomes the URL path.

## Adding a guide

Write it as `src/content/docs/guides/<name>.md`; it appears under **Guides** in the sidebar.
To also list it in an extension's sidebar group, add `<name>` to that extension's `guides`
array in `src/data/extensions.mjs`. The URL stays `/guides/<name>/` either way, and the build
fails if a listed guide doesn't exist. For a guide listed under an extension, `src/routeData.ts`
highlights both sidebar copies and drops Previous/Next links, unless the guide's frontmatter
sets `prev` or `next`.
